# AI-анализатор вакансий

Собственный инструмент для автоматизации поиска, анализа и обработки
вакансий с использованием локальной LLM и браузерной автоматизации.

## Что делает проект

Основной pipeline:

``` text
Сбор вакансий
    ↓
Предварительная фильтрация
    ↓
AI-классификация профессии
    ↓
Анализ требований
    ↓
Сопоставление с профилем кандидата
    ↓
Decision Guard
    ↓
APPLY / REVIEW / REJECT
    ↓
Выбор подтверждённых фактов
    ↓
Генерация сопроводительного письма
    ↓
Валидация письма
    ↓
Автоматизация отклика
    ↓
История и защита от повторной обработки
```

## Основные возможности

### Сбор вакансий

Проект использует единый роутер источников и поддерживает:

- HeadHunter (`hh.ru`)
- Habr Career (`career.habr.com`)

Для каждого источника предусмотрен отдельный адаптер, при этом основной
pipeline работает через общий интерфейс.

### Предварительная фильтрация

До AI-анализа применяются программные правила:

- проверка целевого направления;
- географии;
- опыта;
- дополнительных ограничений;
- decision guard.

Это позволяет отделить жёсткие программные правила от AI-оценки.

### AI-анализ

Для AI-обработки используется локальная LLM через Ollama.

Отдельные модули отвечают за:

- классификацию вакансии;
- структурирование требований;
- оценку соответствия профилю;
- выбор подтверждённых фактов;
- генерацию сопроводительного письма;
- проверку письма.

### Принятие решения

Результат обработки выражается в трёх состояниях:

- `APPLY` — вакансия подходит для отклика;
- `REVIEW` — пограничный случай;
- `REJECT` — вакансия отсеяна.

Часть критических правил реализована программно через `decision_guard`,
поэтому они не зависят только от ответа LLM.

### Работа с профилем

Для сопроводительного письма система отдельно выбирает подтверждённые
факты профиля кандидата. Это позволяет не передавать в письмо
произвольные или неподтверждённые сведения.

### Генерация и проверка письма

После AI-генерации сопроводительное письмо проходит отдельную валидацию
перед дальнейшей обработкой.

### Браузерная автоматизация

Для работы с сайтами используется Playwright.

Автоматизированы операции, связанные со сбором вакансий, открытием
страниц, проверкой уже обработанных вакансий и подготовкой/выполнением
отклика.

Проект также содержит обработку блокировок и диагностические механизмы.

### История и дедупликация

Результаты обработки сохраняются в истории.

Для разных источников используются префиксы ID:

``` text
hh-137310637
habr-1000162215
```

Это позволяет не смешивать вакансии разных площадок при дедупликации и
хранении результатов.

# Архитектура

``` text
aiauto/
├── ai/
│   ├── classifier.py
│   ├── evaluator.py
│   ├── requirements_analyzer.py
│   ├── fact_selector.py
│   ├── cover_letter.py
│   ├── letter_validator.py
│   └── ollama_client.py
│
├── filters/
│   ├── rules.py
│   └── decision_guard.py
│
├── hh/
│   ├── browser.py
│   ├── search.py
│   ├── vacancy.py
│   └── apply.py
│
├── habr/
│   └── ...
│
├── config.py
├── router.py
└── main.py
```

### `main.py`

Главный orchestration-модуль. Объединяет загрузку профиля и истории,
запуск браузера, сбор вакансий, фильтрацию, AI-анализ, принятие решения,
генерацию письма и обработку отклика.

### `router.py`

Определяет источник вакансии по URL и передаёт выполнение
соответствующему адаптеру:

``` text
hh.ru              → hh/
career.habr.com    → habr/
```

### `ai/`

Модули AI-обработки:

- `classifier.py` — классификация;
- `requirements_analyzer.py` — анализ требований;
- `evaluator.py` — оценка соответствия;
- `fact_selector.py` — выбор подтверждённых фактов;
- `cover_letter.py` — генерация письма;
- `letter_validator.py` — валидация;
- `ollama_client.py` — взаимодействие с Ollama.

### `filters/`

Программные правила и decision guard, отделённые от AI-логики.

# Подход к архитектуре

Проект разделяет задачи между обычным программным кодом и LLM:

``` text
Сбор и фильтрация
        ↓
AI-классификация
        ↓
AI-анализ требований
        ↓
Сопоставление с профилем
        ↓
Программные ограничения
        ↓
Итоговое решение
        ↓
Выбор фактов
        ↓
Генерация письма
        ↓
Валидация
        ↓
Браузерная автоматизация
```

Это позволяет менять отдельные этапы системы независимо и не возлагать
критические правила исключительно на LLM.

# Демонстрация

Для просмотра работы проекта рекомендуется использовать скринкаст,
приложенный вместе со ссылкой на репозиторий.

В демонстрации можно показать:

1.  запуск анализатора;
2.  сбор вакансий;
3.  фильтрацию;
4.  AI-классификацию;
5.  анализ требований;
6.  решение `APPLY / REVIEW / REJECT`;
7.  выбор фактов профиля;
8.  генерацию и проверку сопроводительного письма;
9.  работу браузерной автоматизации.
